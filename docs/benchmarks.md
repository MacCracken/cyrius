## Auto-generated, not hand-maintained

The canonical "current" surface is **`/BENCHMARKS.md`** at the repo
root — generated by `scripts/bench-history.sh`, which runs the
three-tier suite (Tier 1: stdlib primitives; Tier 2: data structures;
Tier 3: compiler/toolchain) and writes both a machine-readable CSV
history (`bench-history.csv`) and a human-readable run-comparison
Markdown. Each run captures git commit + branch + UTC timestamp so
regression bisection is grep-then-checkout.

```sh
sh scripts/bench-history.sh           # all 3 tiers (~45s)
sh scripts/bench-history.sh --tier1   # stdlib only (~5s)
sh scripts/bench-history.sh --tier2   # + data structures (~10s)
BENCH_ITERS=1000 sh scripts/bench-history.sh   # override iter count
```

Run at minor closeout (P(-1) "Post-audit benchmarks" step) + whenever
you suspect a regression. The delta column in `BENCHMARKS.md`
auto-highlights drift between the most recent three runs.

## Why this stub exists

Earlier versions of this file (through v5.6.43) bundled binary-size
comparisons, compiler microbenchmarks, and stdlib counts into one
hand-written document — which silently rotted as the project shipped
50+ patches without anyone re-running the numbers. The v5.7.x split
established `size-comparisons.md` as the per-release binary-size
surface; the v5.7.x `scripts/bench-history.sh` introduction
established `BENCHMARKS.md` (root) as the auto-gen perf surface.

This stub stays at `docs/benchmarks.md` so external links (README,
vidya entries, CI workflow's "Required docs exist" check in
`.github/workflows/ci.yml`) keep resolving — but every link here is
a pointer at a more authoritative source.

The original v3.4.15 / 2026-04-11 content was preserved as
[`docs/development/archive/2026-04-11-benchmarks.md`](development/archive/2026-04-11-benchmarks.md)
for historical reference. Numbers there cite retired `cc3` / `Stage1f`
binaries against a stdlib that has roughly doubled in size since;
don't quote them as current.
