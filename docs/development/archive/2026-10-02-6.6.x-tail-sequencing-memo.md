# 6.6.x sequencing: the proposals, the hanging items, and when v6.7.x starts

Inputs: eight premise-checked reviews, plus roadmap.md, roadmap_6.md and state.md at `6bd690d7`. I re-ran four repros myself for this memo: string interning, the brace list, the struct copy, and SIGPIPE. All four are live.

## 1. Do the proposals before v6.7.x, or after?

**Do the tooling proposals before v6.7.x, except P3 and the execution half of P5. Move the DCE compaction arc out of the 6.6.x tail.**

The order is not forced by dependencies. P1, P2, P4, P5-A and P6 need nothing from the language arc, and the language arc needs nothing from them.

- **P2 does not want `const fn` or `comptime`.** It is bytes in. cbt writes them out as escaped literals, and a 1.9 MB blob already round-trips exactly on all five targets with no compiler change. P3's `const fn` returns a scalar, so it could not bake a table anyway.
- **The only coupling runs from P1 into v6.7.x.** The bounds-checked mode (C2) and an instrumented coverage build each want a `[build]` key. P1's precedence order (argument > environment > manifest > default) should exist before they add more environment variables.

Three things decide it:
1. **Cost.** The five tooling proposals come to about three releases, almost all cbt and lib. Only P6 edits compiler-source `lib/alloc.cyr`, and the full release gate covers that.
2. **Ecosystem churn.** P4 and the fold bundles make every `[lib]` producer regenerate. v6.7.x brings a reserved-word survey and a struct-layout migration. Two sibling waves run one after the other cost less than two overlapping.
3. **Three items are defects, not features:**
   - `[build] test` is inert, yet 41 manifests and two sibling CIs rely on it. kashi's 393 assertions have never run in CI.
   - `--poison` checks nothing in kriya and puka, because they never use the freelist.
   - 73 of 76 published sidecars name `assert`, and their bundles never call it.

What genuinely has to come before v6.7.x is compiler work:
- Traits, trait-bounded generics and `bool` will be built on the struct-parameter convention, the `<T>(` call detectors and the type-name ladders. All three are wrong today.
- Every new top-level form would have to be added to 7 forks unless pass 1 is shared first.

## 3. The hanging items

**(a) Promote now: live, silent or security-relevant, and cheap.** These are review finds, so they need your promotion.

- **String interning aliases a NUL-bearing literal onto its own storage (B0a).** `var A="a"; var X="a\0a"; var B="zzzz";` then `load8(X+2)` returns 122, not 97, with rc 0 and no warning.
  - The fix is one condition at `src/frontend/lex.cyr:2505`. The prototype self-hosts, passes seed-derive, and leaves cycc byte-identical.
  - sankoch carries a hand-written proof to avoid it.
  - **Goes into 6.6.15**, followed by a byte-diff of ecosystem binaries to find victims.
- **6.6.16, compiler:**
  - `var T: i64[3] = {1,2,42}` at module scope stores bytes: T[2] reads 0.
  - Pointer-mode struct `q = a` is wrong (q.y keeps its old value). `G = a` into a global is also wrong, and `a = q` crashes with SIGSEGV.
  - Overload dispatch on a `Str` global, inferred ones included, prints the header bytes.
  - `g<i32>(..)?` exits 139, and `var v = g<i32>(..);` silently drops the payload.
  - A nested fn crashes with SIGILL; it should be refused with a named error.
  - In kmode, a global initialiser that names an enum compiles to a dead store.
- **6.6.16, security:**
  - **Plain-socket SIGPIPE.** `sock_send_all` to a closed peer kills the process with signal 13. This is CVE-66's class at P1, so a CVE-68 candidate. It needs kavach's `basic` profile to allow `sendto`; the kavach patch tags first.
  - **`cyrius deps` tag traversal.** A tag can create directories outside the cache, and the refusal message then tells the user to `rm -rf` that outside path. CVE-62 class.

**(b) The rest of the 6.6.x tail, by release** (full lists are in section 4):
- **6.6.15:** the Ed25519 `sig_len == 64` check and the ServerKeyExchange curve binding (both in the function the ECDHE work rewrites); a private wine prefix for the PE size gate; the sit-fsck lookup; the sigil-repo items (TPM rooted paths, `/tmp` names, the cold-trial workaround, the false "Windows threads run inline" note); the stale-doc fixes listed in (d).
- **6.6.16:** CA EKU, Windows accept inheriting FIONBIO, `fd_wait_ready` error mask, libssl session cache (fall back to `SSL_CTX_ctrl`) plus the sticky error, Windows `THREADS_CONCURRENT=1` (already passes on cass: 5/5 and 54/54), agnos `setsockopt` stub, the cycc include fallback honouring `CYRIUS_HOME` (lex.cyr), one shared type-name resolver (sizeof for u*/f*/bool; scalar annotations stop prefix-matching and refuse unknown names), the `#deprecated` gaps, cwd-independence for 6 gates, the guide's `fn use()` example plus a gate axis, and the `element_typed_array` sentinel.
- **6.6.17 to 6.6.19:** DRY pass-1; the ESYSXLAT compile-time fold (about 593 KB, a third of `cycc-native-aarch64`'s code); a "compaction declined: \<why\>" note for DCE; the missing `sxtw`; the LSP's 1 MB read buffer sized by fstat; `lib sync --full` re-locking; the `_toml_key_at` hyphen boundary; the log/ws/ws_server fold bundles; x86-macOS real threads plus `async_await_readable_ms` on macOS, agnos and Windows.

**(c) Backlog (6.x, never 7.x):**
- After v6.7.x and before RISC-V:
  - the DCE compaction arc (decision 2 below);
  - `lib/net.cyr` §4 per-arch socket numbers, the remaining syscall families, and AF_UNIX (default yes; 19 repos hand-roll it).
- TLS, platform and sibling-owned: native TLS capability limits (sending intermediates is the first to promote); the 300-entry PEM index; the Windows trust-store CTL; Windows symlink long paths; agnos #48 write deadline (needs agnos's ABI change first); mirshi older-kernel coverage; tantu; DWARF, incremental compilation, auto-vectorisation and the FREED holes.
- Language candidates and design forks: `comptime` blocks; raw string literals; a string-literal array initializer (a candidate for the v6.7.x B list); `[build].modules` errors attributed to the entry file; P1 profiles and the `target` key; P6 guard pages; whether the P5 denominator should follow the `[lib]` surface; the enum duplicate-symbol noise (folds into B1).
- Siblings: bayan, crab, mabda, bote, aethersafha, sankhya. kriya's `k_isatty` stack overrun should go out as kriya 1.7.4 straight after the 6.6.15 tag.

**(d) Drop, or already resolved (with the evidence):**
- **ir_dce / CLASSIFY_CF backlog line:** the wrappers were deleted at 6.5.50 (`374f361d`), and CLASSIFY_CF is wired through RA_SCAN_LOOPS (`x86/decode.cyr:393-401`).
- **I7 / race-gate port flake:** shipped in 6.6.14 (CHANGELOG C7).
- **Bare `var a[N]` question:** subscripting one is now a hard error that names the typed spelling. Close it; overrun checks go to C2.
- **Already shipped:** P5's prerequisite (6.6.8 bite 9) and P1's "adjacent to `.2`" guard (6.6.2).
- **Stale text to correct in 6.6.15:**
  - P2's "zero newlines" constraint has been obsolete since `#@srcline` (v6.5.24).
  - C1's `ir_const_fold` premise is false: it is an x86-ELF peephole that runs only under opt-in `CYRIUS_IR=3`.
  - P3's "computed initializer is folded" is false: an image scan shows a deferred runtime store.
  - The syscall-families entry is out of date: Tier-1 wrappers shipped in 6.6.8, getrlimit in 6.6.12, and aarch64 does have setrlimit (164).
- **Shapes to drop:** P4's `dev-stdlib` key and `[lib] umbrella`; P6's manifest/interposition shape; P1's `[build] features`; cxvm as a coverage VM; the const-eval VM rung (declined 2026-07-07); the Rosetta timebase item (ecb has no Rosetta, so drop it as an unsupported configuration); sakshi's qemu-static item (does not reproduce in CI).

**(e) Three decisions only you can make**
1. **Promote list (a).** Default: yes. B0a goes into 6.6.15; the rest into 6.6.16.
2. **Move the DCE compaction arc out of the 6.6.x tail.** Default: after v6.7.x and before RISC-V, which is still 6.x.
   - Why: today the arc's first half (PE + x86 Mach-O) has 0 consumers; the 18 repos that use DCE build aarch64. aarch64 needs its own repair model, which rv64 will reuse, and it is cheaper after the ESYSXLAT fold.
   - Every target is correct today; the unsupported ones only skip the shrink.
   - This saves 2–4 releases before 6.7.0. The honest "declined" note ships now.
3. **A named struct argument over 8 bytes is a COPY**, matching 6.6.12's field-argument copy and fixing the case where a callee mutates the caller's struct. Default: COPY, settled before traits inherit it. The only blast radius is cyrius's own tests and guide.

Other defaults I'm taking unless you say otherwise:
- P4 option 2 (this reverses the v6.5.10 "union" stance).
- P5 A now, B in v6.7.x.
- P6 widened to `alloc()` redzones.
- `[build] test` gets WIRED, after measuring the 24 repos with named deps.
- `output` stays a default, and `init --bin` writes to `build/{PROJ}`.
- DCE stays opt-in, so a `dce` key is worth adding.
- `#phf`: shabdakosh's own generator, no compiler builtin.
- P2 stays in 6.6.x.
