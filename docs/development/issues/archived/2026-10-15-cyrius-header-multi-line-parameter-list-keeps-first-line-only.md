# `cyrius header` keeps only the first line of a multi-line parameter list, which drops parameters and misses a vector parameter on a continuation line — RESOLVED

> ✅ **RESOLVED in v6.7.14** (TL-3, `2922dacc6`: `cyrius header` reads a wrapped parameter list to its own `)`. No decision needed: the header prints the fn's real parameters, and 6.7.13's vector-parameter refusal applies as written. The span is bounded by the buffer, not the declaration's line; a newline, CR or tab inside it is a blank (`_hdr_blank`); and a list of blanks alone is `(void)`. The filed ml.cyr prints `cyr_val b3(cyr_val x, cyr_val y);` and refuses a3 by name (`'a3' takes 'v: u8v16': a SIMD vector parameter, which no C11 type carries; no prototype written`), rc 1; it printed `cyr_val b3(cyr_val x);` / `cyr_val a3(cyr_val x);` at rc 0. `tls_native_hkdf_expand_label` prints its nine parameters (it printed four). A one-line blank list, `fn e1( )`, now prints `(void)` as well (it printed `e1()`). ## Reproduction

```sh
printf 'fn b3(x,\n      y): i64 { return 0; }\nfn a3(x,\n      v: u8v16): i64 { return 0; }\n' > ml.cyr
build/cyrius header ml.cyr; echo "rc=$?"
```

```
/* Auto-generated by cyrius header -- do not edit */
...
cyr_val b3(cyr_val x);
cyr_val a3(cyr_val x);

#endif /* CYRIUS_FFI_H */
rc=0
expected: cyr_val b3(cyr_val x, cyr_val y);  and a3 refused by name (rc 1), as the one-line form is
```

The same file compiles: `(cat ml.cyr; printf 'var r = b3(1, 2);\nsyscall(60, r);\n') | build/cycc` gives cycc rc 0, and
the binary exits 0. The one-line spelling of a3 is refused:

```sh
printf 'fn a1(x, v: u8v16): i64 { return 0; }\n' > one.cyr
build/cyrius header one.cyr > /dev/null; echo "rc=$?"
```

## Root cause

`cmd_header` (cbt/quality.cyr, around line 2395) scans line by line. For a public fn it finds the `(` on the
declaration's line and then calls `pe = _hdr_close(hbuf, ps, le, 0)`, where `le` is that LINE's end. `_hdr_close`
returns `lim` when no `)` closes before it, so the parameter span is cut at the first newline. The parameter printer
and `_hdr_vparam(hbuf, ps, pe)` (6.7.13) both read `[ps, pe)`, so they see only the first line's parameters.
`_hdr_ret_of(hbuf, hn, ps)` is bounded by the buffer end, which is why the return class comes out right.

## Proposed fix

Bound the `_hdr_close` call by the buffer end (`hn`), not the line end, so the span runs to the matching `)` across
lines. The parameter printer then has to treat a newline plus indentation inside the span as whitespace. Rows in the
header gate: the b3 / a3 repro above (b3 prints both parameters, a3 is refused by name, rc 1), and
`tls_native_hkdf_expand_label` prints nine parameters. Mutation: line-bounded `_hdr_close` turns those rows RED.
